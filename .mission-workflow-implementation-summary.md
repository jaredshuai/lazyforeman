## Workflow Architecture

### 6-Step Pipeline

```
Step 1: parseMissionMarkdown
    ↓ Parse and validate mission.md (quality gates enforced)
Step 2: extractAssertions
    ↓ Investigator Agent extracts validation assertions
Step 3: generateFeatures
    ↓ Planner Agent generates features (one-to-one mapping)
Step 4: validateCoverage (HARD GATE)
    ↓ Coverage Validator enforces 100% assertion coverage
Step 5: saveMissionData
    ↓ Persist all data to SQLite (missions, assertions, features, validations)
Step 6: exportArtifacts
    ↓ Export assertions.json and features.json
```

### Key Features

1. **Crash Recovery**: Uses `runStep()` pattern from Phase 1
   - Each step journaled to SQLite
   - Resume from last completed step after crash
   - No re-execution of completed steps

2. **Hard Gate Enforcement**: Coverage validation must pass at 100%
   - Orphan assertions block execution
   - Duplicate claims block execution
   - Clear error reporting with actionable next steps

3. **Type Safety**: Strict TypeScript types throughout
   - No type assertions or `any` types
   - Full IDE autocomplete support
   - Compile-time error detection

4. **Data Integrity**: Foreign key constraints enforced
   - Mission record created before metadata
   - Assertions reference valid missions
   - Features reference valid missions
   - Validations reference valid missions

## Bug Fixes During Implementation

### 1. Foreign Key Constraint Issue
**Problem**: `missions_metadata` requires `missions` record to exist first
**Solution**: Create mission record before saving metadata in Step 5

### 2. JSON Metadata Issue
**Problem**: `missionId` missing from exported assertions.json metadata
**Solution**: Merge `missionId` into metadata when exporting artifacts

### 3. Map Deserialization Issue
**Problem**: `duplicateClaims` Map becomes plain object after journal deserialization
**Solution**: Handle both Map and plain object cases in `saveValidationResult()`

### 4. Type Safety Issue
**Problem**: Database `status` field string not assignable to union type
**Solution**: Add explicit type assertion for status field
