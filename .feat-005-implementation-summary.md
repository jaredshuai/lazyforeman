## Conflict Detection Algorithm (ADR-0003 §6.2)

### Priority Order
1. **Boundary Violation** (highest priority)
   - Checks if proposal suggests doing something in the outOfScope list
   - Returns: major conflict → require_user_decision

2. **Constraint Violation**
   - Checks if proposal violates architecture constraints
   - Detects patterns: "不用", "改用", "替换为", "换成"
   - Returns: major conflict → require_user_decision

3. **Goal Impact**
   - Checks if proposal affects implementation approach
   - Detects keywords: "改为", "替换", "取消", "不实现"
   - Returns: minor conflict → multi_ai_adjudication

4. **No Conflict**
   - Technical adjustments that don't affect vision
   - Returns: none → auto_approve

### Keyword Matching Logic

Enhanced to handle:
- **Chinese text**: Matches complete phrases like "社交登录"
- **Parenthetical options**: Extracts and matches "社交登录（Google/Facebook/Twitter）"
- **Main phrases**: Matches both with and without parenthetical content
- **Whitespace variations**: Handles both Chinese and English spacing

## Integration with IssuesHandler

The vision conflict detection is integrated as **step 3** in the IssuesHandler flow:

```
1. Load issues from repository
2. Classify issues
3. Vision conflict detection (NEW) - for ALL blocking issues
   - If major conflicts found → pause + send_signal immediately
4. Handle architecture_conflict (category-specific)
5. Handle dependency_missing (category-specific)
6. Decide action for other scenarios
```

This ensures vision conflicts are caught early, before any category-specific handling.

## Key Design Decisions

1. **Conservative Strategy**: When uncertain, judge as major conflict
2. **Mock AI First**: Phase 2.2 uses rule-based detection, not real LLM
3. **Extensible**: Easy to replace with real LLM in future phases
4. **Complete Priority Chain**: Boundary > Constraint > Goal ensures proper conflict prioritization
5. **All Blocking Issues**: Vision detection runs on ALL blocking issues, not just specific categories
